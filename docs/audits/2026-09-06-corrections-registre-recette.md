## Précisions de sécurité et de persistance

- Le profil de création est partagé entre formulaire et commande. Les versions historiques montre 1.5/1.6 restent distinctes ; automobile 1.2 n’est pas une mise à niveau implicite des dossiers existants.
- L’édition générique accepte uniquement les champs scalaires déclarés modifiables du schéma exact. La commande refuse champs système, listes, doublons, clés inconnues, valeurs invalides et révision périmée ; elle fusionne les autres champs, attribue une provenance déclarative privée et écrit la chaîne d’intégrité.
- Les validations partagées et le gestionnaire serveur résident sous `scripts/lib`, inclus dans le déploiement Functions. Ils ne dépendent pas d’un fichier runtime situé sous `src`, exclu par la configuration Functions.
- La synchronisation générique ne retire pas les médias ou rappels lorsque ces états ne font pas partie du brouillon. La première édition crée le parent de brouillon privé actif si nécessaire, sans réactiver un brouillon supprimé. Les tests émulateur couvrent les commandes Admin, pas à eux seuls cette première transaction client sous Rules.
- Les médias génériques réutilisent les composants privés communs avec `cartularyId` et `binaryId`. La publication passe par le panneau serveur partagé ; aucun média n’est présélectionné et aucune branche de marque ou d’identifiant ne détermine les fonctionnalités.
- Le rapport générique réutilise la mécanique d’impression existante. Les pages sont choisies et une confirmation de contenu privé est exigée. Il reprend uniquement les données enregistrées, liste les médias sans inclure les originaux et ne prétend pas confirmer un enregistrement PDF effectué par le navigateur. La pagination du fichier effectivement imprimé reste à contrôler visuellement.
